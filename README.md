# NovelForge · 铸书 — AI 长篇小说创作工坊

**设定 → 大纲 → 章纲 → 正文 → 审校 → 定稿**,分层生成、全程可编辑的本地 Web 工作台。
基于对 GitHub 上 15+ 个 AI 写小说开源项目与 Re3/DOC/WriteHERE 等学术系统的系统调研([调研报告](docs/research.md)),取各家之长、避各家之坑。

```bash
pip install -r requirements.txt
python main.py          # 浏览器打开 http://127.0.0.1:8000
```

> 无 API Key 也能跑:内置「离线演示」mock 模型,开箱即可体验全流程;配置真实 Key 后一键切换。

## 为什么是「更好的」

调研发现 2026 年头部项目的共识与痛点,逐条落实在本项目中:

| 调研发现 | NovelForge 的做法 |
|---|---|
| 纯向量检索/纯模型记忆都撑不住长篇一致性 | **三层记忆**:世界观+角色档案 → 滚动摘要+上一章结尾 → BM25 检索相关旧情节,外加**伏笔清单**,按预算组装每次生成的上下文 |
| 「结构化状态回写」正在取代向量派(天命/wfcz10086 的教训) | 章节**定稿时**用快模型抽取人物状态变化与伏笔埋设/回收,回写故事圣经,下一章自动携带最新状态 |
| 大纲粒度不足是质量下限(DOC 的核心结论) | 两级细化:逐章「目标-阻碍-转折+钩子」大纲 → 场景级章纲(节拍)→ 正文严格对拍 |
| 人工监督是刚需(书童模式最受欢迎) | 所有产物可编辑;润色/修订**先流式预览、确认后才采用**,原稿不被覆盖 |
| 去 AI 味是最受欢迎的润色能力 | 润色提示词内置 AI 味负面清单(套话、排比腔、模板动作、形容词堆砌) |
| 强/快模型分工 + 费用透明是刚需 | **双模型档案**:强模型(大纲/正文/审校)、快模型(摘要/状态抽取);用量统计与 token 估算展示 |
| 拆书仿写是各家标配 | txt 导入按「第X章」正则自动拆章,可续写、可研结构 |
| 部署复杂劝退(MongoDB/Docker/固定宿主) | **零外部服务**:SQLite 单文件 + 4 个 pip 依赖,`python main.py` 即用 |
| 供应商锁定、硬编码模型名腐化 | OpenAI 兼容协议任意接入(DeepSeek/GLM/Qwen/Kimi/OpenAI/Ollama),设置页在线增删与测试 |
| 生成黑盒、断流不可恢复 | 全部生成走 SSE 流式可见;生成在服务端线程完成,断流后结果照常落库 |

## 功能总览

- **设定页**:梗概/文风(含风格预设)、世界观生成、角色档案表(手工+AI)、伏笔登记簿
- **大纲页**:一键生成全书章纲(卷+章+钩子),逐章标题/概要可编辑,手动增删章
- **写作页**:章纲节拍生成、**上下文透视**(实时查看本章将注入哪些前情/角色状态/旧情节/伏笔)、正文流式生成、去 AI 味润色
- **审校页**:评分卡(总分+四维)、带定位的问题清单、修改建议、按意见修订(预览→采用)、定稿(自动更新摘要+人物状态+伏笔)
- **导出页**:TXT / Markdown / DOCX,txt 拆书导入,作品统计与模型用量
- **设置页**:多模型档案(名称/BaseURL/Key/模型/温度/max_tokens)、强/快模型指定、生成参数(章字数/上下文预算/摘要窗口/检索条数)、连接测试

## 架构

```
web/                     单页前端(原生 JS,无构建)
app/
  config.py              设置合并(.env < UI),强/快模型解析与降级
  db.py                  SQLite 存储(项目/角色/章节/伏笔/用量/日志)
  llm.py                 OpenAI 兼容客户端:流式、JSON 容错解析、重试、mock
  memory.py              三层记忆与上下文组装(字符二元组 BM25)
  prompts.py             全部中文提示词模板
  stages.py              流水线编排(生成/审校/修订/定稿/导入)
  routes.py              FastAPI 路由(生成类接口统一 SSE)
  export.py              TXT/Markdown/DOCX 导出
tests/e2e_smoke.py       端到端冒烟测试(mock 全流程,25 项断言)
```

**流水线**:世界观 → 角色 → 全书大纲 → 章纲(节拍)→ 正文 → 润色 → 审校 → 修订 → 定稿(摘要 + 状态回写),每一步的产物都可手工编辑后继续。

## 快速开始

1. **安装**:`pip install -r requirements.txt`(Python 3.10+;DOCX 导出需要 python-docx,已含在 requirements 中)
2. **启动**:`python main.py [端口]`,默认 http://127.0.0.1:8000
3. **配置模型**:侧栏「⚙ 设置」→ 任选一家 OpenAI 兼容服务填 Base URL + API Key + 模型名 → 「测试」→ 保存
   - DeepSeek:`https://api.deepseek.com/v1` + `deepseek-chat`
   - 智谱:`https://open.bigmodel.cn/api/paas/v4` + `glm-4-plus`
   - Ollama 本地:`http://127.0.0.1:11434/v1` + 模型名
   - 也可复制 `.env.example` 为 `.env` 预置
4. **创作**:新建作品 → 写一句话梗概 → 生成世界观(改到满意)→ 生成角色 → 生成大纲(30 章起步)→ 逐章「章纲 → 生成正文 → 润色 → 审校 → 修订 → 定稿」→ 导出

**推荐模型分工**:强模型用能力较强的 chat 模型(写作质量主要取决于它);快模型用便宜快速的模型(摘要/状态抽取),单章成本可降低约 40%。
