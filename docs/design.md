# CastNovel(铸书)总体设计

> 版本:v0.2 · 更新:2026-10-28
> 本文是项目的唯一权威设计文档,基于四轮开源生态调研([research.md](research.md),40+ 项目/系统 + 2024-2026 学术前沿)提炼。
> 每个设计决策都标注了来源与理由;未实现的部分明确标注阶段。
> 命名说明:初名 NovelForge,因 GitHub 已有同名项目(RhythmicWave/NovelForge)更名 **CastNovel**(cast:铸造,亦指「角色阵容」)。

## 1. 定位与用户画像

**一句话**:面向个人作者的「AI 主笔、人做主编」长篇小说生产流水线 —— 本地优先、数据自有、成本透明。

| 用户画像 | 核心诉求 | 对应能力 |
|---|---|---|
| 网文作者(主力) | 日更 6000 字不断更、设定不崩、过审稿 | 三层记忆 + 门禁 + 批量连写 + 拆书学习 |
| 完本作者/写手工作室 | 质量可控、成本可控 | 强/快模型分档、审校评分卡、用量统计 |
| AI 写作爱好者 | 快速试玩、数据在本地 | 零部署、mock 模式、OpenAI 兼容任意接入 |

## 2. 设计原则

1. **人为主编**:AI 产草稿,关键决定(采用/回滚/覆盖)永远由作者拍板;危险操作前自动快照。
2. **不指望模型记忆**:长程一致性 = 结构化状态回写 + 检索 + 程序化校验,模型只负责"写",不负责"记"。
3. **确定性优先**:能用代码校验的不用模型(LLM 不负责算术结论 —— 墨枢原则);模型输出一律视为提案。
4. **成本显式**:强/快模型分档路由,字符级用量统计,生成过程全程可见(SSE),失败诚实降级不假装成功。
5. **零部署**:SQLite + 4 个 pip 依赖,`python main.py` 即用;任何功能不允许引入常驻外部服务。
6. **可扩展的方法论**:提示词与规则集中管理,向"用户可插拔 Skill"演进(goink 模式)。

├──────────────────────────────────────────────────────────────────┤
│ stages.py  流水线编排                                             │
│   设定→角色→大纲→章纲→正文(门禁)→润色→审校→修订→定稿→批量      │
├──────────────┬───────────────────┬───────────────────────────────┤
│ memory.py    │ llm.py            │ export.py                     │
│ 三层记忆组装  │ OpenAI 兼容客户端  │ TXT/MD/DOCX/EPUB              │

├──────────────┴───────────────────┴───────────────────────────────┤

### 4.1 数据模型

| 表 | 关键字段 | 说明 |
|---|---|---|
| projects | worldview, style_ref, volumes(JSON) | style_ref=文风样本,注入正文提示词 |
| characters | name(UNIQUE per 项目), role, profile, **status** | 故事圣经·人物层;status 随定稿更新 |
| chapters | idx, beats, summary, content, status, review, **gate** | status: planned/drafting/draft/reviewed/final;gate=门禁报告 JSON |
| foreshadowing | title(UNIQUE), planted_ch, payoff_ch, status | 伏笔:open/resolved |
| plotlines | title(UNIQUE), start_ch, last_ch, status | 情节线:active/done |
| chapter_versions | chapter_id, content, note | 自动快照(重生成/采用前)+手动快照 |
| usage_stats | stage, prompt_chars, completion_chars | 成本透明(≈tokens 按 1.6 字/Token 估算) |

### 4.2 关键时序

**单章生成**:`正文请求 → 组上下文(三层记忆+文风样本)→ 强模型流式生成 → 程序化门禁(字数/人物覆盖/8-gram 重复率)→ 落库(draft)`

**定稿回写**:`定稿 → 快模型生成 120 字摘要 → 快模型抽取状态 JSON(人物状态/伏笔 plant|resolve/情节线 start|advance|end)→ 事务式回写故事圣经 → status=final`

**批量连写**:`选 planned 且无正文的章节 → 逐章[章纲(缺才生成)→正文→(可选审校)→定稿] → 事件流推送进度 → 连续 2 章失败熔断`

## 5. 核心子系统设计

### 5.1 记忆与上下文(v0.2 已实现;v0.3+ 演进)

**三层组装**(每章生成前,预算 `context_chars` 默认 14000 字):

| 层 | 内容 | 预算 |
|---|---|---|
| 静态层 | 世界观(2200)+文风(300)+文风样本(900)+角色档案(每条 280,>8 人按相关性挑选) | ~4000 |
| 序列层 | 前情摘要(近 6 章逐章 240 字,更早只留标题)+上一章结尾 1400 字(口吻衔接) | ~3500 |
| 检索层 | 以「梗概+类型+本章概要」为查询,对旧章摘要+开头 400 字做**字符二元组 idf 加权检索**,取 Top3(每条 300) | ~1000 |
| 状态层 | 待回收伏笔清单(≤8 条)+人物当前状态(嵌在档案行内) | ~800 |

**演进**:
- v0.3 **Lorebook 兼容引擎**(World Info 机制详见 research.md 十一节):设定条目 = 六字段核心(`keys` 主键 / `secondary` 次键(AND-ANY|ALL、NOT-ANY|ALL)/ `content` / `constant` 常驻 / `order` 注入顺序(大=更深)/ `budget` 预算),扫描缓冲区命中才注入,常驻条目优先、按序填充至预算耗尽;先实现该子集,**导入导出兼容 SillyTavern lorebook JSON**,直接复用生态数千份现成 worldbook;角色/伏笔即「带生命周期包装的 lorebook 条目」——伏笔命中本章节拍词时自动注入。
- v0.3 **两步矛盾检查**(ConStory-Checker,[arXiv:2603.05890](https://arxiv.org/abs/2603.05890)):按错误类目(时间线/人物/世界观/事实细节/叙事)抽取可疑片段 → 两两核验带证据链;实证显示事实细节与时间线错误占主导、随长度线性增长。
- v0.4 **可选向量检索**:配置了 embedding API 时自动启用(余弦+MMR 重排),否则维持 BM25;向量维度绑定档案名防跨模型污染(墨枢)。
- v0.4 **信息边界过滤**(dramatica-flow/novel-studio):人物带「知识台账(事实+出处章)」,上下文编译时按 POV 过滤——人物不该知道的内容不进其可读上下文;与「读者认知状态」同属视角状态层。
- v1.0 **时间性事实**(jarvis-write + Narrative World Model):人物/设定事实绑定 `[start_ch, end_ch]`,查询"第 N 章时的状态";上下文注入时只取 `start_ch ≤ N` 的事实,并把 `end_ch = N-1` 的变化作为"刚发生的事"注入。
- v1.0 **章节提交链 + 分支**(webnovel-writer + ST 分支继承):定稿即 CHAPTER_COMMIT,状态/摘要/索引均为只读投影;支持从任意提交分叉时间线、并行再生、择一合回正典。

**学术背书**:NstAgent([arXiv:2609.35759](https://arxiv.org/abs/2609.35759),清华 2026)验证了同构路线——**双向叙事状态**(人物快照 + 过去事件 + 未来义务/未回收伏笔),写手只见「大纲+状态+检索证据」,永不喂原文,每章一次原子 JSON 更新;10 万字场景下一致性显著优于滚动摘要基线,且差距随长度扩大。本项目的伏笔账本即「未来义务」,三层记忆即其检索证据层。

### 5.2 状态与一致性(三层防线)

```
第1道 写前:上下文即约束(状态卡注入,模型"读到"最新事实)
第2道 写后·程序化门禁(零 token,已实现):
      字数 ≥ 目标50%(warn)/80%(info)
      人物覆盖:圣经角色在正文中的命中数,全未命中 → warn
      重复率:与近三章 8-gram Jaccard > 12% → warn
第3道 写后·模型审校(强模型 JSON 评分卡:总分+四维+带定位问题清单)
```

**演进**:
- v0.2 已实现**确定性 lint 规则集**(13 条 AI 味模板规则 + 破折号配额,advisory 级并入门禁;规则数据化可扩展);
- v0.3 **两步 span 级管线**升级(oh-story/Humanizer-zh/arXiv:2409.14509):片段检测(行号+规则)→ 带专家改写例的按类目定点重写,偏删除;规则文件外置可编辑。
- v0.3 **读者认知状态**(goink/oh-story):新增 `reader_knowledge` 投影——读者已知(正文出现过)/人物已知(区分视角)/伏笔期待;定稿时与状态一起抽取,审校时提示"读者尚不知 X,此处反转是否过早"。
- v0.4 **设定变更提案-批准流**(show-me-the-story):AI 修改设定一律先出提案,作者批准才入账。
- v1.0 **事实账本**(webnovel-writer):状态库为唯一权威,摘要/检索索引全部为只读派生投影,提供一致性自检命令;模型输出一律"提案",经校验才入账(ai-novel-studio 原则)。

### 5.3 质量体系

- **审校评分卡**(已实现):总分+四维(情节推进/人物一致性/文笔/节奏)+带类型与严重度的问题清单+可执行建议;修订先预览后采用。注意:学术实证(LitBench)显示 LLM 绝对打分与人类一致率仅 ~73%,**成对比较更可靠**——评分卡保留用于用户可读性,候选择优一律用 pairwise(见 5.5)。
- **去 AI 味**(已实现负面清单 + 文风样本;🔮 v0.3 升级为两步 span 级管线):学术结论("Can AI Writing Be Salvaged?",[arXiv:2409.14509](https://arxiv.org/abs/2409.14509))很明确——**抽象风格指令无效**,有效的是:①带标注例句的片段检测(具体 tell 词表)→ ②按类目改写(定义+专家改写例),偏删除;禁止整段自我润色。本项目的文风样本注入采用**续写式**(作为上文而非"模仿指令"),与 [arXiv:2509.24930](https://arxiv.org/abs/2509.24930) 的 99.9% 风格一致结论一致。
- **字数保障**(已实现门禁检查;后备方案):AgentWrite 式逐节拍字数预算([arXiv:2408.07055](https://arxiv.org/abs/2408.07055))——单次输出仍不达标时,按节拍拆段分次生成再拼装。
- **质量回归**(远期):固定 3 个基准项目(现实向/玄幻/悬疑)+ 固定 mock 评测 prompt,提示词改动后跑分对比(jarvis-write 的 evals gate 思路),防止"改提示词 A 变好 B 变坏"。

### 5.4 版本与级联

- **版本(已实现)**:重生成/采用新稿前自动快照 + 手动快照;一键回滚(回滚前再快照,永不丢稿)。
- **级联大纲影响分析**(🔮 v0.4,jarvis-write):修改第 i 章概要 → 询问影响范围 → 列出受影响的下游章节(摘要/正文标"失配")→ 用户勾选 → 级联重生成摘要。v0.2 的门禁重复率检查已能自动发现"正文与改后大纲失配"的案例。

### 5.5 模型路由与成本

- **双档案**:strong(世界观/大纲/章纲/正文/审校/修订)、fast(摘要/状态抽取);实测建议 DeepSeek 单章正文+定稿组合成本可控制在分级计费(≈¥0.02-0.05/千字 级别,以供应商定价为准)。
- **候选拉样 + 成对择优**(🔮 v0.4,Re3/Plan-and-Write/StoryAlign):章纲与"黄金三章"正文生成 N=3 候选,用快模型做**成对 A/B 评判**(评委可靠性实证支持 pairwise 而非绝对打分)选出最优;CreAgentive 实测千章成本 <$1/100 章,拉样成本可控。
- **失败降级**:API 重试 3 次(退避);批量连写连续 2 章失败熔断;所有失败在 UI 可见,不静默吞掉。

### 5.6 安全与健壮性

- 数据全本地(SQLite + data/ 目录);API Key 只存本地库,可留空走 mock。
- 生成在服务端线程执行,客户端断开不影响落库(对比 AI_NovelGenerator 新版"刷新不保证恢复"的痛点)。
- 上下文全部出自本地状态库,无第三方内容注入面;导入 txt 全程 UTF-8 显式处理(避开 Long-Novel-GPT 的乱码重灾区)。

## 6. UI 信息架构

```
侧栏:作品列表 | +新建 | mock 提示横幅 | ⚙设置(模态)
设定页:作品信息(梗概/文风/文风样本/风格预设)→ 世界观(生成/编辑)
        → 角色档案表 → 伏笔登记簿 → 情节线
大纲页:章数+生成(可覆盖)→ 卷卡片 → 章节表(行内编辑/选中)→ 章纲编辑
写作页:章节选择器+状态+字数+门禁徽章 → 批量连写工具条+事件日志
        → 上下文透视(fold)→ 概要/章纲 → 正文编辑器(流式)→ 生成/润色/保存
审校页:运行审校 → 评分卡+问题清单+建议 → 修订预览(采用/放弃)→ 定稿
导出页:统计(章数/字数/调用/tokens)→ 四格式导出 → 拆书导入
```

交互约定:文本编辑显式保存(脏标记 + 切换确认);所有生成按钮流式反馈;预览-采用模式用于任何"覆盖旧稿"的操作。

## 9. 风险与对策

| 风险 | 对策 |
|---|---|
| 提示词改动引发质量回退 | 质量回归基准(5.3);mock 全流程测试保证功能不回退 |
| 强模型长文输出不稳定(字数/截断) | 门禁字数检查 + 批量熔断;LongWriter 式"计划-分节-拼装"列为后备方案 |
